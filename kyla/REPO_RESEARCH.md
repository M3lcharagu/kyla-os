# KYLA Open-Source Repository Research

Research constraints: prefer free/open-source, low-resource, cloud-first projects that can support a 2012 MacBook Pro (2 cores, 8–16GB RAM) and iPhone 11. Trading focus includes R3 TEMPERANTIA, especially XAUUSD/Nas100 workflows; an open-source project is not assumed to provide market data, broker access, or profitable signals.

## ROUND 1 — Trading / Quant

- **kernc/backtesting.py** — https://github.com/kernc/backtesting.py — What: Lightweight Python framework for quickly backtesting trading strategies and inspecting results. — Room: R3 TEMPERANTIA (strategy research for XAUUSD/Nas100 once OHLCV data is supplied). — **USEFUL** — Reason: Small, notebook-friendly and CPU-suitable for fast hypothesis testing; keep slippage, spread and walk-forward checks explicit.
- **mementum/backtrader** — https://github.com/mementum/backtrader — What: Mature Python backtesting and trading framework with strategy, broker, indicator and analyzer abstractions. — Room: R3 TEMPERANTIA (reusable strategy prototypes and paper/live adapter experiments). — **USEFUL** — Reason: Broad ecosystem and low local resource cost, but its older maintenance profile means pin dependencies and test integrations.
- **QuantConnect/Lean** — https://github.com/QuantConnect/Lean — What: Open-source algorithmic trading engine for research, backtesting and live trading across multiple asset classes. — Room: R3 TEMPERANTIA (cross-asset research and execution architecture). — **USEFUL** — Reason: Strong research/execution model and cloud-first option; local Lean runs may be heavier than the 2012 Mac, so prefer remote execution.
- **TheSnowGuru/PyTrader-python-mt4-mt5-trading-api-connector-drag-n-drop** — https://github.com/TheSnowGuru/PyTrader-python-mt4-mt5-trading-api-connector-drag-n-drop — What: Python/EA connector for MetaTrader 4 and 5 live or paper trading. — Room: R3 TEMPERANTIA (MT4/MT5 bridge for broker-side XAUUSD/Nas100 execution). — **USEFUL** — Reason: Directly matches the MT4/MT5 requirement and is light enough for a broker/VPS sidecar; license and broker compatibility need review before production.
- **michiTrader/tradetropy** — https://github.com/michiTrader/tradetropy — What: Algorithmic trading framework with order-flow/footprint support plus backtesting and live/replay workflows. — Room: R3 TEMPERANTIA (order-flow confirmation and footprint research). — **USEFUL** — Reason: One of the closest open-source matches for footprint-style analysis; validate its data-feed and instrument assumptions on XAUUSD/Nas100.
- **chriskl/orderflow** — https://github.com/chriskl/orderflow — What: Builds footprint candles from real-time trades without requiring a heavyweight charting platform. — Room: R3 TEMPERANTIA (streaming order-flow/footprint signals). — **USEFUL** — Reason: Focused and potentially low-resource for a cloud/VPS service; usefulness depends on an available tick/trade feed and careful aggregation validation.
- **freqtrade/freqtrade** — https://github.com/freqtrade/freqtrade — What: Free, open-source Python crypto trading bot with backtesting, hyperoptimization and exchange execution. — Room: R3 TEMPERANTIA (architecture reference only). — **SKIP** — Reason: Its core exchange and crypto market model has no direct MT4/CFD execution value for XAUUSD/Nas100; do not make it the primary stack.
- **ccxt/ccxt** — https://github.com/ccxt/ccxt — What: Unified API library for many cryptocurrency and prediction-market exchanges in multiple languages. — Room: R3 TEMPERANTIA (optional crypto data/exchange adapter). — **SKIP** — Reason: Excellent general exchange plumbing but not a MetaTrader/CFD bridge for XAUUSD/Nas100, and it adds little to the primary workflow.

ROUND 1 COMMITTED

## ROUND 2 — AI Agents / Developer Tooling

- **langgenius/dify** — https://github.com/langgenius/dify — What: Collaborative workspace for agentic workflows and RAG pipelines with model and tool support, deployable on cloud, VPC or self-hosted. — Room: R1 HUMANITAS (Kimi K3-facing agent and research workspace). — **USEFUL** — Reason: Strong orchestration fit and flexible deployment; connect Kimi K3 through a supported or OpenAI-compatible provider, while keeping heavy inference remote rather than on the 2012 Mac.
- **ollama/ollama** — https://github.com/ollama/ollama — What: Open-source runner and API for getting local or remote-compatible LLM workflows running with models including Kimi-family and other popular models. — Room: R1 HUMANITAS (local dev runner and model gateway). — **USEFUL** — Reason: Very simple API and low-friction developer experience; use only small local models on the old Mac and route Kimi K3 inference to a capable remote endpoint.
- **run-llama/llama_index** — https://github.com/run-llama/llama_index — What: Framework for building LLM applications over private data, including indexing, retrieval and agent workflows. — Room: R2 PATIENTIA (RAG over personal/client knowledge). — **USEFUL** — Reason: Direct RAG fit with model/provider flexibility, so Kimi K3 can remain the reasoning layer; keep embeddings, indexing and large corpora on a remote service when local RAM is tight.
- **qdrant/qdrant** — https://github.com/qdrant/qdrant — What: Open-source vector similarity search and database for production retrieval workloads. — Room: R2 PATIENTIA (durable memory and semantic retrieval). — **USEFUL** — Reason: Focused service that can be cloud-hosted or run as a small sidecar; it complements Kimi K3 without requiring a local GPU, but collection sizing and backup policy matter.
- **n8n-io/n8n** — https://github.com/n8n-io/n8n — What: Self-hostable workflow automation platform connecting apps, APIs and AI steps. — Room: R4 INDUSTRIA (business operations and repeatable automations). — **USEFUL** — Reason: Broad integrations make K3-triggered workflows practical and cloud-first; run it remotely or with conservative worker limits because a full self-hosted stack is heavy for the 2012 Mac.
- **huginn/huginn** — https://github.com/huginn/huginn — What: Self-hosted agents that monitor events, feeds and websites and act through notifications or downstream workflows. — Room: R4 INDUSTRIA (monitoring and event-driven operations). — **USEFUL** — Reason: Mature, CPU-oriented automation with no model lock-in; pair its triggers with a Kimi K3 API call and keep scraping compliant, rate-limited and remote where needed.

ROUND 2 COMMITTED

## ROUND 3 — Content / Business / QA / Security

- **yt-dlp/yt-dlp** — https://github.com/yt-dlp/yt-dlp — What: Feature-rich command-line audio/video downloader supporting many video sites and formats. — Room: R5 (content intake and clipping pipeline). — **USEFUL** — Reason: Small, scriptable and CPU-light for downloading source media before local clipping or remote Kimi K3-assisted selection; respect platform terms and rights.
- **mifi/lossless-cut** — https://github.com/mifi/lossless-cut — What: Cross-platform lossless video and audio cutter built around fast stream copying. — Room: R6 (rapid video clipping and export). — **USEFUL** — Reason: Avoids re-encoding for many cuts, making it unusually suitable for an old Mac; use FFmpeg-compatible files and reserve expensive transcodes for a remote worker.
- **twentyhq/twenty** — https://github.com/twentyhq/twenty — What: Open-source CRM for managing contacts, companies, opportunities and sales workflows. — Room: R7 (client and relationship management). — **USEFUL** — Reason: Gives KYLA a self-hostable CRM data layer that Kimi K3 can summarize or act on through APIs; database and background services are better hosted remotely than on the 2012 Mac.
- **TryGhost/Ghost** — https://github.com/TryGhost/Ghost — What: Open-source publishing platform for memberships, subscriptions, blogs and newsletters. — Room: R8 (newsletter and publishing operations). — **USEFUL** — Reason: Direct newsletter/business fit with a mature web workflow; let Kimi K3 draft and classify content while keeping human approval, subscriber data controls and deliverability checks explicit.
- **microsoft/playwright** — https://github.com/microsoft/playwright — What: Web testing and automation framework for Chromium, Firefox and WebKit. — Room: R9 (browser QA and regression testing). — **USEFUL** — Reason: High-value automated QA and browser coverage; run headed browsers sparingly on the old Mac and prefer CI/cloud runners for parallel tests.
- **ggerganov/whisper.cpp** — https://github.com/ggerganov/whisper.cpp — What: C/C++ implementation of Whisper speech recognition that can run locally on CPU and produce transcription data. — Room: R10 HUMILITAS (captioning and accessible content). — **USEFUL** — Reason: A practical local captioning option with quantized CPU models; small models may fit the Mac, while long-form batches should run remotely and captions should be reviewed before publishing.
- **mitmproxy/mitmproxy** — https://github.com/mitmproxy/mitmproxy — What: Interactive TLS-capable HTTP proxy for inspecting and debugging application traffic. — Room: R11 (security and integration QA). — **USEFUL** — Reason: Lightweight, scriptable verification for APIs and webhooks that Kimi K3 workflows depend on; use only on systems and traffic Mel is authorized to test.
- **caddyserver/caddy** — https://github.com/caddyserver/caddy — What: Fast extensible web server and reverse proxy with automatic HTTPS. — Room: R13 (secure service edge and deployment hygiene). — **USEFUL** — Reason: Small operational footprint and simple TLS defaults suit cloud-first KYLA services; still restrict admin endpoints, rotate secrets and verify proxy headers.

ROUND 3 COMMITTED
